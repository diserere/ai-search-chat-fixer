# Отчёты о тестировании при разработке ChatGPT Chat Fixer

- Тестовая (целевая) среда: ChatGPT (https://chatgpt.com)
- Исполнитель: Claude Code через Claude in Chrome (реальные нажатия клавиш, `isTrusted: true`)
- Способ установки скрипта: код скрипта выполнен в контексте страницы (эквивалент `@grant none`)

***

### Исследование дефолтного поведения поля ввода

**Устройство поля ввода.** Редактор ProseMirror (`div.ProseMirror[contenteditable="true"]`, markdown-режим) внутри `form[data-chatgpt-composer]`. Кнопка отправки — `button[type="submit"]`, появляется только при непустом поле.

**Нативные клавиши:**
- `Enter` — отправка.
- `Shift+Enter` — новый абзац `<p>` (эталон переноса строки).

**Программная вставка переноса:**

| Способ | Результат |
|--------|-----------|
| `execCommand('insertText', false, '\n')` | **Отправка сообщения** |
| `execCommand('insertParagraph')` | **Отправка сообщения** |
| `execCommand('insertLineBreak')` | Перенос `\n` внутри абзаца + лишний хвостовой `\n` — отличается от нативного |
| Синтетический `KeyboardEvent` Shift+Enter (`isTrusted: false`) | Игнорируется |
| Подмена `shiftKey` у trusted-события через `Object.defineProperty` | Новый абзац `<p>`, идентично нативному Shift+Enter |

**Вывод.** ProseMirror трактует `insertParagraph` и `insertText('\n')` как Enter (отправка), а синтетические события игнорирует. Единственный способ получить поведение, идентичное нативному, — подмена модификаторов у самого trusted-события в фазе capture.

***

### Отчёт по тестированию скрипта (версия 1.0.0)

**Протестированная последовательность.**
1. Ввод многострочного тестового промпта (`docs/testing/prompts/testing_prompt.md`, ~30 строк, включая markdown-списки) с `Enter` между строками, отправка по `Ctrl+Enter`.
2. Тестовое сообщение: `e` × 10 → `a` × 2 → `s` × 2 → `c`.
3. Двухстрочный запрос отчёта (`Enter` между строками), отправка по `Ctrl+Enter`.

**Анализ маркеров.**
- `n` (нет скролла) — отсутствуют. После 14 переносов поле прокрутилось (`scrollTop` 141 из `scrollHeight` 421 при `clientHeight` 265), каретка в видимой области.
- `F` (сбой) — отсутствуют.
- Преждевременных отправок нет ни в одном из трёх сообщений.

**Интерпретация поведения.**
1. **`e` (Enter)** — новый абзац + скролл. Успех (10 повторений + ввод промпта).
2. **`a` (Alt+Enter)** — новый абзац + скролл. Успех (2 повторения).
3. **`s` (Shift+Enter)** — новый абзац + скролл, нативное поведение. Успех (2 повторения).
4. **`c` (Ctrl+Enter)** — отправка сообщения. Успех (3 отправки за сессию).

**Замечания.**
- Двойной `Enter` в markdown-списке выходит из списка — так же, как нативный `Shift+Enter`.
- Не проверено: `Cmd+Enter` на macOS, ввод через IME, установка через Tampermonkey/Violentmonkey (требует ручной проверки).

**Итоговый вердикт.** Версия 1.0.0 работает в соответствии с ТЗ.
